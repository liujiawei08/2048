# 2048（C 语言终端版）

一个可以在终端里运行的经典 2048 小游戏：纯 C11、零第三方依赖、跨平台
（Windows / Linux / macOS），带 ANSI 256 色渲染、撤销、本地最高分、音效，
以及基于 Expectimax + Alpha-Beta 剪枝的 **AI 自动游玩**模式。

## 功能特性

- 经典 4×4 规则，严格保证"一次移动中每个方块最多合并一次"
- ANSI 256 色方块渲染：2 青、4 绿、8 黄……2048 红底白字高亮
- 方向键 / WASD 双套操作，Windows 与类 Unix 终端均无回显即时响应
- **撤销**：最多回退 100 步（环形缓冲区，O(1) 压栈弹栈）
- **本地最高分**：`highscore.txt` 持久化，顶栏实时显示
- **音效反馈**：移动 / 合并 / 撤销 / 拒绝 / 胜利 / 终局
  （Windows 用 `Beep()`，类 Unix 用终端响铃）
- **AI 自动游玩**：按 `a`，AI 用 Expectimax 搜索 + Alpha-Beta 剪枝
  计算最佳方向并立即执行

## 操作说明

| 按键 | 功能 |
|---|---|
| `W` `A` `S` `D` 或 ↑ ← ↓ → | 向对应方向移动 |
| `U` | 撤销一步（最多 100 步） |
| `A` | AI 自动计算并执行最佳一步 |
| `R` | 重新开始 |
| `Q` | 退出（自动保存已破的纪录） |

## 编译指南

### 方式一：CMake（推荐，跨平台）

需要 CMake ≥ 3.10 和任意 C 编译器（GCC / Clang / MSVC / MinGW）。

```sh
mkdir build && cd build
cmake ..
cmake --build .
ctest                 # 运行单元测试
```

生成物：`game`（Windows 下为 `game.exe`）与 `unit_tests`。

Windows + MinGW 用户：构建时自动加 `-static` 静态链接，
生成的 exe 可拷贝到没有装 MinGW 的机器上直接运行。

### 方式二：Makefile

```sh
make          # 生成 game.exe（Windows）或 game（类 Unix）
make check    # 编译并运行单元测试
make clean    # 清理编译产物
```

### 方式三：直接调用 gcc

```sh
gcc -Wall -Wextra -std=c11 -O2 -o game main.c game_logic.c ui.c ai.c
gcc -Wall -Wextra -std=c11 -O2 -o test test.c game_logic.c   # 单元测试
./test
```

## 项目结构

```
├── main.c          程序入口与主循环，只做流程编排
├── game_logic.h/.c 逻辑层：棋盘、移动合并、撤销、胜负、最高分（无 printf）
├── ui.h/.c         UI 层：ANSI 渲染、读键、音效
├── ai.h/.c         AI 层：Expectimax + Alpha-Beta，只读棋盘推演
├── test.c          单元测试（只链接逻辑层，18 个用例）
├── Makefile        简易构建
└── CMakeLists.txt  CMake 跨平台构建（含 CTest）
```

层间只通过头文件通信：UI 层和 AI 层都依赖逻辑层，主循环依赖全部三层，
逻辑层不依赖任何上层模块。

## 核心算法解析

### 移动合并：slide_left 两步法

整个移动逻辑只实现了一个函数 `slide_left(int b[4], int *gained)`：

1. **压缩**：把非零元素依次压到左边；
2. **合并**：从左往右扫描，相邻相等就合并，合并后**跳过后一个元素**。

"跳过"保证了一次移动中每个方块最多合并一次：
`2 2 2 2` 得到 `4 4 0 0`，而不会连锁合并成 `8 0 0 0`。
四个方向通过反转/转置复用这一个函数（右=反转+左移+反转，
上=转置+左移+转置，下=转置+右移+转置），算法时间复杂度 O(n²)，n=4。

### AI：Expectimax + Alpha-Beta

2048 是随机博弈（移动后系统随机出块），教科书 Minimax 的"对手有意对抗"
假设不成立。本项目采用其在随机博弈下的标准推广 **Expectimax**：

- **Max 层**：AI 在四个方向中选择期望收益最大的一步，本层做
  Alpha-Beta 剪枝；
- **Chance 层**：枚举每个空格生成 2（90%）或 4（10%）的所有可能，
  按概率取期望值——期望值不是 min/max，故 Chance 层不剪枝，
  保证概率加权的正确性。

叶节点用启发式评估函数打分，四项加权：
**空格数**（腾挪余地）、**平滑度**（相邻数值接近，容易合并）、
**单调性**（行列尽量单调，大数压角）、**最大块角落奖励**。
数值先取 log2 再评估，使大合并的收益呈线性，评估更稳定。

为保证低配置机器也瞬间响应，搜索采用**迭代加深 + 节点预算**：
从深度 1 逐步加深到 4，单层搜索预算 3 万个节点（毫秒级），
预算耗尽即返回当前最深一层的答案。AI 只在棋盘副本上推演，
绝不触碰真实对局状态。

### 撤销：环形缓冲区

撤销历史是容量 100 的快照环形缓冲区（`Snapshot` = 棋盘 + 分数），
压栈/弹栈均为 O(1)，栈满自动覆盖最早一步。无效移动不入栈，
重开一局清空历史。

## 单元测试

`test.c` 共 18 个用例，覆盖：

| 输入行 | 预期输出行 | 说明 |
|---|---|---|
| 2 2 2 2 | 4 4 0 0 | 两对分别合并，不能连锁成 8 |
| 2 0 2 4 | 4 4 0 0 | 先压缩再合并 |
| 4 4 4 0 | 8 4 0 0 | 只合并最左边一对，第三个 4 保留 |
| 2 2 4 4 | 4 8 0 0 | 不同值各自成对合并 |

另有 NULL 计分指针、四方向冒烟、撤销（空栈/单步/多步）、
最高分不变式等用例。测试只链接逻辑层，不产生任何文件副作用。

```sh
make check        # 或 ctest（CMake 构建时）
```

## 性能说明

- 单步移动 / 胜负判断 / 生成方块：O(n²)，n=4，即 16 次循环量级
- 撤销压栈弹栈：O(1)（环形缓冲区）
- AI 单步决策：深度 ≤ 4、单层节点预算 3 万，实测平均约 70 毫秒
- 静态内存占用：撤销历史约 7 KB，总可执行文件不足 100 KB
