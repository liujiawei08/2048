# 2048（C 语言终端版）

一个可以在终端里运行的经典 2048 小游戏，纯 C 语言（C11）实现，无第三方依赖。

## 文件结构

项目按三层拆分，依赖方向为 main → render / input → game，层间只通过头文件通信：

- `main.c` — 程序入口与主循环，只做流程编排
- `game.h` / `game.c` — 逻辑层：棋盘初始化、随机生成、移动合并、撤销栈、胜负判断
- `render.h` / `render.c` — 渲染层：ANSI 颜色映射、清屏、棋盘输出（只读调用 game 接口）
- `input.h` / `input.c` — 输入层：无回显读键、方向键翻译（Windows conio / Unix termios）
- `test.c` — 单元测试，只链接逻辑层
- `Makefile` — 一键编译（`make` 构建游戏，`make check` 编译并运行测试）

## 编译

有 make 的环境（MinGW / MSYS2 / Linux / macOS）：

```sh
make
```

或者直接用 gcc：

```sh
gcc -Wall -Wextra -std=c11 -O2 -o 2048 main.c game.c render.c input.c
```

Windows 下生成 `2048.exe`，类 Unix 下生成 `2048`。

## 运行

```sh
# Windows
./2048.exe

# Linux / macOS
./2048
```

操作：w/a/s/d 或方向键移动，u 撤销一步，r 重新开始，q 退出。

## 界面配色

方块按数值显示不同颜色（ANSI 256 色转义序列）：2 青、4 绿、8 黄，
16~1024 经过橙、品红、蓝、紫、铜过渡，2048 为红底白字加粗高亮，
超过 2048 为暗紫加粗。
Windows 下程序启动时会自动调用 `SetConsoleMode` 开启
`ENABLE_VIRTUAL_TERMINAL_PROCESSING`；类 Unix 终端原生支持。

## 本地最高分

启动时从程序目录的 `highscore.txt` 读取历史最高分，显示在顶栏
`Score: 当前分  Best: 最高分`。本局分数一旦超越纪录会即时刷新显示；
游戏结束（或中途按 q/r）时若破了纪录，自动把新高分写回文件。
文件不存在或内容损坏时按 0 处理，不影响游戏。

## 撤销功能

`game.c` 内部维护一个最多 100 步的快照栈（`Snapshot`：棋盘 + 分数）。
每次有效移动确认后，先把“移动前的棋盘和分数”压栈，再计分、生成新方块；
按 u 时弹栈恢复。无效移动（棋盘没变化）不会污染历史，
按 r 重开会清空历史，防止撤销回上一局。

## 核心算法说明

整个移动逻辑只实现了一个函数 `slide_left(int b[4], int *gained)`，负责把一行向左滑动并合并：

1. 压缩：把非零元素依次移到左边；
2. 合并：从左往右扫描，相邻相等就合并，合并后**跳过后一个元素**。
   这个“跳过”保证了一次移动中每个方块最多合并一次，
   例如 `2 2 2 2` 得到 `4 4 0 0`，而不会错误地连锁合并成 `8 0 0 0`。

四个方向通过数组操作复用这一个函数：

- 左：直接对每行 `slide_left`
- 右：每行反转 → `slide_left` → 反转回来
- 上：棋盘转置 → 每行 `slide_left` → 转置回来
- 下：棋盘转置 → 按“右”处理 → 转置回来

## slide_left 测试用例

| 输入行 | 预期输出行 | 说明 |
|---|---|---|
| 2 2 2 2 | 4 4 0 0 | 两对分别合并，不能连锁成 8 |
| 2 0 2 4 | 4 4 0 0 | 先压缩再合并 |
| 4 4 4 0 | 8 4 0 0 | 只合并最左边一对，第三个 4 保留 |
| 2 2 4 4 | 4 8 0 0 | 不同值各自成对合并 |
